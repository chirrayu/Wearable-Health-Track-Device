# Deployment guide

## 1. Deploy the backend to Render

1. Push this repository to a private Git repository and create a new Render Blueprint from `render.yaml`.
2. In the Render service environment, set a unique `ADMIN_USERNAME` and a strong, unique `ADMIN_PASSWORD`. `SECRET_KEY` is generated by the Blueprint. Add AWS and Firebase variables only when those integrations are required.
3. Deploy, then open `https://<your-service>.onrender.com/`. It must return `{"status":"ok","app":"Triage AI Backend"}`.
4. Copy the public `https://<your-service>.onrender.com` URL into `software/frontend/app/src/main/java/com/example/healthmonitor/NetworkConfig.kt`, then build a signed Android release APK.

The backend refuses to start in production if default admin credentials or the default JWT secret are used.

### Recovering the admin password without Shell access

If you changed `ADMIN_PASSWORD` after the service was first started, set
`RESET_ADMIN_PASSWORD=true` in Render **Environment**, deploy once, and log in
with the current `ADMIN_USERNAME` and `ADMIN_PASSWORD`. Remove the reset
variable immediately and deploy again; leaving it enabled resets the password
on every service restart.

## 2. Build and provision the ESP32

From `hardware`, install PlatformIO and run:

```powershell
pio run
pio run --target upload
pio device monitor --baud 115200
```

The firmware is compiled with the ESP32 CA certificate bundle. When the Android app provisions Wi-Fi over BLE, it now also sends the deployed backend host, port, and scheme; a Render URL is automatically configured as HTTPS on port 443. Do not put Wi-Fi credentials or deployment secrets in `main.cpp`.

Before field use, create the soldier record in the app/backend and make its ID match the suit ID sent during provisioning (the first-boot fallback is `SOLDIER-001`).

## 3. Android release

Open `software/frontend` in Android Studio, confirm `NetworkConfig.kt` points to the deployed HTTPS URL, then use **Build > Generate Signed Bundle / APK**. Store the keystore outside this repository. Install the signed APK and test login, BLE provisioning, a vitals POST, GPS update, and WebSocket updates against the Render URL.

## Security notes

- `software/backend/photo.env` was historically tracked and may contain credentials. Remove it from Git history before sharing the repository and rotate any values it contained.
- Keep the repository private: it contains health and location telemetry code.
- Render's free tier is unsuitable for dependable production monitoring because services can sleep; use an always-on plan for operational deployments.
